# Security and the public demo

This page covers the public demo: it says honestly what a visitor to the public live URL can and cannot do,
and where each control lives. Report a problem by opening an issue (no secrets in issues, please).

## Deployment shape
- **Network.** FalkorDB is never published. Only Caddy (TLS) is exposed, and it routes `/api/*` to the API, `/mcp` to MCP-over-HTTP and everything else to the UI. Bodies are capped at 1 MB.
- **Client IPs.** The API trusts `X-Forwarded-For` only from Caddy (it is reachable only on the internal network), so per-visitor rate limits are per visitor.
- **Defaults.** Keyless: simulated GitHub, deterministic investigator, no LLM spend, `FAULTLINE_PUBLIC=true`.

## Threat model for the public URL

| A visitor tries to… | What happens | Where |
|---|---|---|
| approve or re-choose actions on someone else's incident | 403. Choose and approve need the run's token (returned only to the visitor who started the run; the graph stores only its sha256) | `api.py::_run_token_ok`, `writes.set_run_token`, `run_token.cypher` |
| approve as a made-up person | 422. The approver must be an active person in the tenant graph; their relation to the component is shown | `approver.cypher` |
| merge into a real GitHub repo | impossible by default (simulated GitHub). With `FAULTLINE_GITHUB=real`, approval also needs `X-Faultline-Approver-Key` | `api.py::_approver_ok` |
| delete knowledge with forget | runs on a clean-room `GRAPH.COPY`, deleted afterwards. The live tenant graph is immutable to visitors (an admin key is needed to forget for real) | `api.py::memory_forget` |
| poison preflight records | unkeyed preflights are assessed on a clean-room copy and never recorded. Only the keyed GitHub Action records | `api.py::preflight` |
| spend money on the LLM | 403 without the operator's `X-Faultline-LLM-Key` (and no key is configured on the public demo) | `api.py::run_scenario`, `::brain_ask` |
| run arbitrary Cypher | templates only, plus guarded read-only text2cypher (masked text, no writes or `GRAPH.*`, CALL allowlist, bounded paths, EXPLAIN check, RO_QUERY with a 3 s timeout) | `graph/guard.py`, `graph/ro.py` |
| read brain sessions, turns or run tokens through text2cypher (hosted MCP `run_cypher_readonly`, brain tier 3) | a label/property policy: the `Session` and `Turn` labels, `HAS_TURN`, `Run.token_sha` and the turn/session-only properties (`text`, `refs`, `user`) are refused in any form (label, property access, map projection, map key, string or parameter naming them, `properties(…)`, `n[$p]`), and the returned rows are filtered: a Session/Turn node, a `sess-…` id or a denied property never reaches the caller | `graph/guard.py::check_private`, `::redact_rows`, `graph/ro.py::run_guarded` |
| read another tenant | refused by the RO wrapper ownership check, the MCP key → tenant binding and the per-tenant ACL user | `graph/tenant.py`, `mcp_server/context.py`, `deploy/users.acl.template` |
| exhaust resources | per-visitor and global rate limits on every acting route, at most 4 concurrent runs (checked and reserved under one lock), 3 SSE streams per visitor (50 in total; the slot is taken at check time under a lock and released when the stream ends), PROFILE capped globally, MCP 30 calls/min/key and 30/min per IP without a key (bounded LRU), new runs, clean-room copies, brain scratch copies and re-arms refused (429) while FalkorDB has more than `engine.max_waiting` queries queued or uses more than `engine.max_memory_fraction` of maxmemory; old run graphs (`eval_<t>_api_*`) collected at startup and every few runs, except graphs in use (a PENDING intent, a live lease, an execute job or reconciler working on it, activity within `engine.gc_touched_ttl_min`, an open incident idle less than `engine.gc_open_max_idle_h`); a collected run answers 410 and its event stream sends `collected` and stops | `api.py::_limit`, `::_stream_slot`, `::_shed_load`, `::gc_run_graphs`, `graph/engine_info.py::check_capacity`, `mcp_server/http.py` |
| fill the live graph through brain questions | on the public demo a visitor's question (its Run, tool calls, evidence, session turns) is recorded in a per-tenant brain scratch copy, replaced after `brain.scratch_ttl_min` or `brain.scratch_max_runs` and collected; the citation guard reads that same copy. Only the operator (admin or LLM key) records in the tenant graph | `brain/scratch.py`, `api.py::brain_ask` |
| take a component's id as a session id | session ids are server-issued `sess-…` (a supplied id is validated and prefixed) and the turn write refuses an id another node already has | `brain/ask.py::session_id`, `writes.W_TURN` |
| read visitors' questions through the hosted MCP server | `session_history` there returns only the caller's own sessions (user = its key id), and visitors' turns live in the brain scratch copies, not the tenant graph the MCP server reads | `mcp_server/tools.py::session_history` |
| run two data scenarios that need different warehouse modes at once | 429: one DuckDB warehouse, one fixture mode at a time (a per-process gate, first come first served, plus an fcntl file lock next to the DuckDB file so `make eval`, the CLI and the API never use it together; same-mode runs share it, a data repair rebuilds it alone) | `scenario.py::ModeGate` |
| run code through an LLM-authored transform | a proposed transform must be exactly one `CREATE [OR REPLACE] TABLE|VIEW <its own target> AS SELECT …` (parsed by DuckDB; no COPY, ATTACH, INSTALL, LOAD, PRAGMA, SET, CALL, EXPORT, IMPORT, file/network/environment functions, `FROM '<file>'` or quoted identifiers); the build turns external access off and locks the configuration after loading the sources, runs with a scrubbed environment (no API secrets) and swaps a finished build in atomically; transforms are restored to hash-pinned pristine copies on every mode switch and re-arm | `repair.py::validate_transform_sql`, `pipeline/run.py`, `warehouse.py::run_step`, `repair.py::restore_pristine` |
| frame the UI (clickjacking on approve) | `Content-Security-Policy: frame-ancestors 'none'`, `X-Frame-Options: DENY`, and a self-only CSP | `deploy/Caddyfile` |
| break other visitors' runs with Re-arm | Re-arm resets only the tenant graph and its simulated world. Runs live in their own `eval_*` graphs with their own simulated GitHub | `actions/github.py::client(world)` |

## What is NOT protected (accepted for a demo)
- **Brain history.** It is readable by anyone who knows a user id (the user id is client-asserted); ids are pseudonymous browser-session ids, and on the public demo history lives only in the current brain scratch copy.
- **Re-arm** is rate-limited (1/min per visitor, 20/hour globally) but open; it restores the seeded data.
- **The approver identity** is client-asserted: the approve and reject bodies name an approver, and the server checks only that the name is an active person in the tenant graph (422 otherwise), not that the caller *is* that person. It is a demo of the approval *flow* (choose ≠ approve, plan hash, run token), not of identity. Against real GitHub (`FAULTLINE_GITHUB=real`) the approval also needs the operator's `X-Faultline-Approver-Key`, so only the key holder can make a real merge; the named approver is still what that key holder typed.
- **Error details.** Clients get a generic message and a request id for engine, OS, subprocess and GitHub errors (the detail is in the server log under that id), so raw FalkorDB errors, file paths and pipeline stderr never reach a visitor; this covers HTTP errors, job errors, stage notes and run-index notes (`public_errors.py`). Our own messages (a refused precondition, a busy warehouse, a budget) are shown as they are.
- **Text2cypher residue.** The private-data policy is syntactic plus a row filter: a query may still learn that unlabeled nodes exist whose `role` is `user` or `assistant`, or count nodes, without reading a session id, a turn's text or a token hash.
